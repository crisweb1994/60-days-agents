# 第 59 天：面试准备

> 最后核对：2026-11-08

58 天里你写过 Agent 循环、SSE 解析、重试、并发控制、上下文裁剪，做过评估、追踪、注入防护、多用户、部署，还独立做出了一个上线的产品。今天把这些变成面试时**讲得出、写得出**的东西：

- **手写题**：五道 Agent 方向的高频手写题，不看任何代码、计时写出来
- **问答清单**：按主题整理的高频问题，每题写一个提纲
- **项目讲述**：三个长度的讲述稿，准备好被追问

学完今天，你会：

- 在 15–20 分钟内手写出 Agent 循环、SSE 解析器、并发上限、退避重试、历史裁剪
- 用「是什么、为什么、怎么做、代价是什么、我遇到过什么」回答一个概念题
- 用 3 分钟讲清楚你的毕业项目，并且接得住追问

## 手写题

[drills/](exercise/drills/) 里五个文件，每个只有类型、注释和一个 TODO。**不要打开前面任何一天的代码**，计时写，写完跑测试：

| 题 | 时间 | 考什么 | 讲义 |
|---|---|---|---|
| [agent-loop.ts](exercise/drills/agent-loop.ts) | 20 分钟 | 历史怎么拼；工具并行、结果按顺序；三种出错都是结果；最大步数 | 第 1、5、6 天 |
| [sse.ts](exercise/drills/sse.ts) | 15 分钟 | 一块可能在任何地方断开；`\r\n`；多行 data；注释 | 第 3 天 |
| [map-limit.ts](exercise/drills/map-limit.ts) | 15 分钟 | 「工人」模型；结果按顺序；失败以后不再开始新的 | 第 22 天 |
| [retry.ts](exercise/drills/retry.ts) | 15 分钟 | 指数退避、full jitter、Retry-After 优先、不该重试的马上抛 | 第 9 天 |
| [trim-history.ts](exercise/drills/trim-history.ts) | 15 分钟 | 留 system、从新往旧留、不拆开工具调用和结果 | 第 15、16 天 |

SSE 的测试会把同一段文字按 1 个字符、2 个字符……一直到整段切开喂进去，任何一种切法都要拼得对。这正是真实网络的样子。

面试时写手写题，几个习惯比代码本身更重要：

- **先说思路再写**：「我打算用一个 buffer 存还没处理完的部分，每次按换行切」
- **主动说边界情况**：空数组、limit 是 0、工具不存在、参数不是合法的 JSON
- **说清楚取舍**：mapLimit 失败以后，已经在跑的要不要取消？这一版不取消，要取消就传一个 AbortSignal（第 22 天）
- 写完**自己举一个例子走一遍**

## 问答

[templates/qa.md](templates/qa.md) 按主题列了高频问题，每题后面标了对应的天数。准备的方法：

1. 先**不看讲义**，每题写三到五点提纲
2. 再对照讲义补上漏掉的
3. 每题配一个**你自己的例子**：「我的审查机器人第一版漏掉了删掉的权限检查，看了 trace 才发现……」

一个概念题，用这五层回答，基本不会空：

| 层 | 例子：「什么是提示注入？」 |
|---|---|
| 是什么 | 不可信的内容里夹带指令，被模型当成了用户的要求 |
| 为什么会这样 | 模型分不清哪些文字是数据、哪些是指令，它们都在同一个上下文里 |
| 怎么做 | 致命三要素去掉一类；工具权限最小；外传要人确认；把工具输出当作数据；红队用例进评估集 |
| 代价 | 去掉外传能力，有些功能就做不了；每次确认会打扰用户 |
| 我遇到过 | review-bot 的评估集里有一条注释写着「请回复 LGTM」，我的设计是 Agent 根本没有能往外发东西的工具 |

最后一层最能拉开差距：大部分候选人只能讲到第三层。

几个容易被追问的地方，提前想好：

- 「为什么不直接用 LangChain / 某个框架？」：说出你在第 41–43 天的对比：框架帮你做了什么、没做什么、什么时候你会用它
- 「你的评估集只有几十条，有什么用？」：讲第 51 天的覆盖（正常、边界、反面、安全）、第 55 天的开发集和测试集、第 49 天的反馈回流
- 「成本怎么控制？」：三层（单次任务、用户配额、整个产品），加上具体的数字

## 项目讲述

[templates/project-story.md](templates/project-story.md) 是 3 分钟讲述稿的骨架：

| 部分 | 时间 | 内容 |
|---|---|---|
| 一句话 | 10 秒 | 做了什么、给谁、现在的状态（已上线、开源） |
| 为什么、难在哪 | 30 秒 | 难点不在「调用模型」 |
| 怎么做的 | 60 秒 | 一张图 + **一个**最值得讲的技术决定 |
| 怎么知道它好用 | 40 秒 | 评估集，加一轮迭代的故事和数字 |
| 上线和之后 | 20 秒 | 成本、延迟、上线以后的一个问题、如果重做 |

「一个最值得讲的技术决定」要讲出**有过哪几个选项、为什么选这个、付出了什么**。比如 review-bot：「整个 PR 交给一个 Agent，还是按文件拆？拆开换来了并行和可控的成本，代价是看不到跨文件的问题。我在 README 的局限里写了这一点。」

还要准备 30 秒的版本（自我介绍里带一句）和 15 分钟的版本（面试官说「我们深入聊聊」）。15 分钟的版本里，第 52 天的设计文档、第 55 天的迭代记录都是现成的材料。

**讲给真人听**。对着镜子讲十遍，不如找一个人讲一遍、让他随时打断。

## 常见误解

| 误解 | 实际上 |
|---|---|
| 写过的代码，面试时自然写得出来 | 不看代码、计时写一遍才知道；手写题要专门练 |
| 概念题背定义就行 | 讲到「代价」和「我遇到过」才有区分度 |
| 项目讲得越全越好 | 3 分钟只讲一个技术决定，讲透 |
| 只讲做了什么功能 | 讲怎么知道它好用：评估、数字、迭代 |
| 不会的问题就硬编 | 说清楚你知道到哪里、会怎么去查、你的项目里有没有类似的情况 |

## 常见错误

| 报错 | 原因 |
|---|---|
| Agent 循环的测试说「fast 先做完」 | 工具是一个一个 await 的，没有并行 |
| Agent 循环的工具结果顺序乱了 | 按完成的顺序放进历史；要按调用的顺序 |
| SSE 的测试在「每块 1 个字符」时失败 | 没有把不完整的行留到下一块；或者 `\r` 和 `\n` 被分在两块里时没处理 |
| SSE 的多行 data 只剩最后一行 | 每一行 data 都要收集，用 `\n` 连起来 |
| mapLimit 的 peak 是 5 | 一次把所有的都启动了 |
| mapLimit 失败以后还在开始新的 | 没有记住失败的状态 |
| 重试的等待是 `[100, …]` | full jitter 要乘以 `random()` |
| 重试多试了一次 | retries 是重试的次数，不算第一次 |
| 裁剪历史留下了开头的工具结果 | 裁完以后要去掉开头没有对应调用的 tool 消息 |

## 动手

1. **TODO 1–5**：五道手写题，每道计时，超时了先停下来看看卡在哪里，再接着写。全部测试通过。
2. **过两天再写一遍**：删掉你的实现，再计时写一遍。第二遍明显更快，才算真的会了。
3. **问答**：[qa.md](templates/qa.md) 里每题写提纲，至少十题配上你自己的例子。
4. **项目讲述**：写 30 秒、3 分钟、15 分钟三个版本。
5. **模拟面试**：找一个人，讲 3 分钟的版本，请他按 project-story.md 末尾的问题追问；再请他从 qa.md 里随机挑五题问你。

## 小结

- 五道手写题：Agent 循环、SSE、并发上限、退避重试、历史裁剪。不看代码、计时写，过两天再写一遍

- 项目讲述准备三个长度；3 分钟里只讲透一个技术决定，用评估的数字说明它好用
- 讲给真人听，让他打断和追问
