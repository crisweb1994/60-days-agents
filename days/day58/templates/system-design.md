# 设计题：题目

> 面试时 45 分钟大致这样分：澄清 5 分钟、估算 5 分钟、整体设计 15 分钟、深挖 15 分钟、取舍和总结 5 分钟。

## 一、澄清需求

- 用户是谁、要完成什么任务、成功是什么样子（第 51 天）
- 规模：每天多少任务、峰值多少、能等多久
- 约束：预算、数据能不能出境、能不能用外部模型、出错的代价有多大

## 二、估算

| 量 | 假设 | 结果 |
|---|---|---|
| 峰值每秒任务数 | 每天 N 个，集中在 H 小时，峰值 F 倍 | |
| 同时在跑的任务 | 每个任务 W 秒（利特尔法则） | |
| 每分钟的调用、token | 每个任务 C 次调用、T 个 token | |
| 模型服务的限流 | 一个 Key 的 RPM、TPM | 要几个 Key / 提额多少 |
| 每月花费 | 每个任务 X 元 | |
| 一次任务多久 | 关键路径上的步骤 | |

## 三、整体设计

一张图：入口 → 队列 → worker（Workflow 还是 Agent，第 21、52 天）→ 工具 → 存储 → 输出。

## 四、深挖（挑两三个）

- 上下文和记忆：放什么、多长、怎么压缩（第 15–19 天）
- 评估：怎么知道它变好了，评估集从哪来（第 31–33、49 天）
- 可靠性：模型挂了、超时、重试、幂等（第 35、45 天）
- 安全：注入、权限、数据隔离（第 37–39、46 天）
- 成本和延迟：缓存、便宜的模型、并行（第 36 天）
